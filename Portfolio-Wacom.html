Overview

This project is about the wacom product drawing tablet 'driver' that enables the tablet to be used across various different applications (Photoshop and Illustrator as just some examples).

The issue is the software's user experience, which is causing friction between the target users using that tablet.

The aim is to rectify this by identifying opportunities to improve the user expeirence and structure the architecture of the software for the future.

Architecture Understanding the Problem

The goal is to create an experience that is easy to set up and run without the user having to focus, issues present are:

  1. Clunky User Experience that confuses and frustrates market.
  2. Interactions of websites are uninspiring and offer nothing for an expensive piece of equipment.
  3. Information is thrown in without considering the user.

So analysing the current set up and conducting usability test with users was the first step.

I analysed the UX architecture, before making any attempt to fix the UI. I could then begin to identify problems, interview user to understand their pain-points and needs, construct a User Persona and a Empathy Map to design purposefully with intent.

RocketDeveloping a Solution

To develop a solution, it is important to do these three things:

  1. Create UX artifacts, create soltions based on data, not just intuition.

  2. Analyse competitors, what they do well and poorly, one up the former and avoid any of the latter.

  3. Mock up concepts for the wider team, helps to convey ideas than just words alone.

Conclusion

The UX was the biggest improvement with this project, conducting interviews did reveal interesting insights about how the users behaved, how little they would use this, but when they needed to it has to be simple.

I was happy with the end result, even though i didn't necessarily follow material design patterns or NN/g in few areas because of the user feedback i received from testing in the early prototype stage.
